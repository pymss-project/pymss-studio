# macOS 插件测试流程

适用：Apple Silicon（M 系列）、macOS 14 或更高版本。此包用于验证未发布插件能力，采用独立应用名称、标识与数据目录，不替换正式版。它使用临时签名，没有 Apple 公证。

## 1. 安装与确认

1. 核对 `SHA256SUMS.txt`：在下载目录运行 `shasum -a 256 -c SHA256SUMS.txt`，所有项目应为 `OK`。
2. 打开 DMG，将 **Pymss Studio Plugin Test.app** 拖入“应用程序”。如果已存在同名测试应用，先退出并保留旧副本，避免覆盖需要留存的文件。
3. 解压测试工具包。先打开一次测试应用，确认系统允许启动。若提示开发者无法验证，可从“系统设置 → 隐私与安全”允许打开该应用。若系统明确提示文件损坏，先确认校验值及下载完整性；需要排除下载隔离标记时，只针对此测试应用执行：

   ```bash
   xattr -dr com.apple.quarantine "/Applications/Pymss Studio Plugin Test.app"
   ```

4. 可双击 `Open Plugin Test.command` 启动，也可在终端运行 `bash "Open Plugin Test.command"`。它使用 `~/.pymss-studio-plugin-test` 保存测试设置、环境、模型和输出。
5. 在设置中核对版本含 `dev.plugins`，并且 pymss 版本含 `+plugins.20261031`。本包不要执行“更新内核”“同步依赖”或重装运行环境，这些动作会改变正在验证的快照。

**通过条件**：应用正常打开；已有正式版设置、模型和插件未改变；运行环境无需先安装 Homebrew/Python/Rust/Cargo。不要把测试输出目录设置为正式版数据目录。

## 2. 先运行自动检查（约 3–8 分钟）

退出测试应用后，在工具包目录运行：

```bash
bash "Verify Plugin Runtime.command"
```

默认检查 `/Applications/Pymss Studio Plugin Test.app`；安装到其他位置时，可把完整应用路径作为第一个参数。脚本会建立新的测试工作目录，不使用正式版数据，不下载模型，也不删除已有文件。

检查内容：

| 项目 | 预期 |
| --- | --- |
| 实验内核 | 版本与工具包的 `build-info.json` 一致 |
| 默认工具 | 转换、合并、切片、音频信息四个插件就绪 |
| Python RPC | 使用内置解释器创建独立环境，callback 和文本输出成功 |
| Rust RPC | 包内 arm64 程序直接运行，无需用户编译 |
| 输出 | 中文路径、LF/CRLF 正确；重复运行保留旧结果 |
| 错误恢复 | 非 UTF-8 输入明确失败，恢复正常输入后可重试 |
| 依赖隔离 | 同一个依赖的 1.0/2.0 分别运行，目标进程看不到宿主 pymss |
| 卸载 | 移除 A 插件后 B 仍使用自己的 2.0 依赖 |

控制台应全为 `PASS`，其中 `expected rejection` 是故意输入无效 UTF-8 的正常拒绝。最终 `summary.json` 的 `status` 应为 `passed`。

报告保存在 `~/Library/Logs/PymssStudioPluginTest/<时间与进程号>/`，包括 `summary.json`、`console.log` 和本次生成的文件。失败时先保留报告，不要连续重装运行环境。测试只收集系统版本、架构、构建标识、步骤耗时与生成的任务结果，不自动上传。

## 3. 手工验收界面（约 10–15 分钟）

重新启动测试应用，按顺序检查：

| 操作 | 预期 |
| --- | --- |
| 首次进入工具页 | 四个基础工具可以使用，不要求先去市场下载 |
| 转换一段 WAV → FLAC → WAV | 可选择输入和输出，任务完成；输出时长、声道正常 |
| 在任务运行时打开日志，任务结束后关闭 | 原背景保留，深浅主题均正常；结果区域完整可见 |
| 音频信息 | 打开后可直接选择文件，信息加载和结果正常 |
| 清空切片器任一数字字段 | 运行按钮禁用，不提交非法任务 |
| 停用/启用一个基础工具 | 工具入口和插件状态一致；重新启用后可运行 |
| 退出再打开 | 设置和已安装状态恢复，工具仍可用 |

可使用自动检查报告的 `workspace` 中生成的文本文件。测试音频请使用自己的短 WAV 副本，保留原文件。

## 4. 手工安装 Python 与 Rust 工具

1. 在插件页选择“从来源安装”，填入工具包 `plugins/python_rpc_text` 的完整目录路径，确认安装。
2. 在工具页打开“文本转换”，选择 UTF-8 文本和新的输出目录，分别运行 LF 与 CRLF；查看结果文件。
3. 同样安装 `plugins/rust_rpc_text`。两个工具标题相同，可通过插件 ID `example.python_rpc_text` / `example.rust_rpc_text` 区分。
4. 连续运行两次，确认第一次的输出未被覆盖；选择包含非法 UTF-8 的输入时，应出现明确错误，换回正常文件后可继续。
5. 取消正在运行的任务后可再次运行。短文本可能在取消前已经完成，这时不计为取消测试通过；进程级取消另由 CI 回归验证。
6. 在工作流编辑器使用各自的文本转换节点，以字符串常量提供文本路径；完成后结果应标为通用文件，不能误当音频送入编辑器。

可选：使用已安装的本地模型处理一段短音频，检查 MLX 与原有分离功能。该项会涉及模型文件和额外时间，自动检查不执行模型推理。

## 5. 反馈与恢复

请反馈：Mac 芯片、macOS 版本、测试包版本、通过到哪一步、复现步骤、截图，以及自动检查报告中的 `summary.json` / `console.log`。无需提供账号、密钥、Cookie 或无关音频。

测试完成后退出应用即可，正式版可继续使用。不要合并测试数据到正式版目录。删除测试应用或测试数据属于手动可选清理；这套流程不会替你执行删除。
